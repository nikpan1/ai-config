# Working with Codex in this repository

## Objective

Deliver a result that can be verified: a correct change, a trustworthy document, or
a clear answer. First determine the user's goal and definition of done; then gather
only the context needed to complete the task.

## Working principles

- Respect the existing structure, conventions, and unrelated user changes.
- Make safe, reversible decisions independently. Ask for clarification only when a
  choice materially changes the result or requires additional authority.
- Make the smallest change that solves the problem. Do not add adjacent features
  or abstractions without a concrete reason.
- Verify the result in proportion to risk. Run relevant tests or quality checks and
  explicitly identify anything that could not be verified.
- Do not stop at a first draft when the agreed result can be completed in the turn.

## Language

- Use English for durable repository artifacts by default: source code, identifiers,
  comments, tests, technical documentation, plans, and commit messages.
- A user may write in any language. Reply in that language unless they request
  otherwise.
- Preserve or use another language when it is the requested end-user content,
  an established project convention, or a localization requirement.

## Content, research, and documentation

- For claims that depend on current external information, use credible sources. For
  a product, API, or standard, prefer the owner's official documentation.
- Cite the supporting page next to the claim, not a search-results page. Distinguish
  facts, inferences, and recommendations, and state uncertainty where relevant.
- Structure Markdown from conclusion to evidence: brief purpose, key recommendation,
  essential details, and sources.
- Use the content-research skill for analysis or source-backed research.

## Substantial tasks

For a significant change or refactor, create and maintain a plan covering scope,
verification points, risks, and definition of done. Do not create a plan merely as
ceremony for a small, unambiguous change.

## Final response

Lead with the outcome, then list material changes and validation performed. Keep the
response concise and match the user's language.
